API / QUICK START

在你的程序里查询学生手册

通过 HTTP 发送一个问题，等待回答完成，再读取返回的 JSON。无需登录，无需 API Key。

以下地址使用当前网站的域名和端口，可直接复制。网站需已启动，调用程序需能访问这个地址。

1. 发送一个问题

POST {{ ask_url }}

请求头设置 Content-Type: application/json，正文只需要 question：

{"question": "国家奖学金的申请条件？"}

问题去除首尾空白后须为 1–500 个字符。每次提问独立处理，不携带上一次问答的上下文。

curl 示例（Bash / Linux / macOS）

curl -X POST {{ ask_url }} \
  -H 'Content-Type: application/json' \
  --max-time 210 \
  -d '{"question":"国家奖学金的申请条件？"}'

-X POST 指定请求方法，-H 指定 JSON 格式，-d 是问题正文；--max-time 210 最多等待 210 秒。

Windows PowerShell 示例 
$body = @{ question = "国家奖学金的申请条件？" } | ConvertTo-Json
$result = Invoke-RestMethod `
  -Method Post `
  -Uri '{{ ask_url }}' `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) `
  -TimeoutSec 210

$result.answer
$result.sources

PowerShell 的换行符是反引号 `，curl 上面使用的反斜杠 \ 不适用于这段命令。

Python 示例（使用标准库，无需另外安装库） 
import json
from urllib.error import HTTPError
from urllib.request import Request, urlopen

body = json.dumps({"question": "国家奖学金的申请条件？"}).encode("utf-8")
request = Request(
    "{{ ask_url }}",
    data=body,
    headers={"Content-Type": "application/json"},
    method="POST",
)

try:
    with urlopen(request, timeout=210) as response:
        result = json.load(response)
    print(result["answer"])
    print(result["sources"])
    print(result["status"], result["complete"])
except HTTPError as error:
    print("HTTP", error.code)
    print(error.read().decode("utf-8"))

2. 等待完整回答

通常需要约 20 秒，复杂问题可能更久。保持这一次 HTTP 请求，服务端会在处理完成后一次性返回 JSON。

建议调用端设置 210 秒超时；网站最多等待 180 秒。等待期间不要反复提交相同问题。

3. 读取回答和引用

返回示例（正文、页码和耗时仅用于说明格式）：

{
  "request_id": "example-request-id",
  "question": "国家奖学金的申请条件？",
  "answer": "这里是根据手册生成的回答 [1]。",
  "sources": [
    {
      "label": "资料1",
      "text": "这里是实际引用的手册原文。",
      "pdf_pages": [12],
      "kind": "handbook",
      "web_sources": []
    }
  ],
  "status": "answered",
  "complete": true,
  "elapsed_seconds": 20.1,
  "warnings": []
}
字段在程序中怎么使用
answer展示给用户的回答正文。
sources引用资料列表；读取 text 看原文、pdf_pages 看 PDF 页码。网页补充资料的标题和链接位于 web_sources。
statusanswered 表示已回答；其他状态见下方，可能需要澄清问题或核对证据。
complete是否完整生成。false 时提示用户本次回答未完整生成。
warnings引用检查等警告；非空时应提醒用户核对回答与引用。
request_id、question、elapsed_seconds分别用于标识本次结果、确认对应问题和展示处理耗时。

HTTP 200 表示成功取得结果，仍需结合 status 和 complete 判断如何展示：

  • needs_clarification：问题需要补充信息；abstained：资料不足，暂未给出确定答案。
  • partial_answer：依据有限，只给出了部分回答；unverified：引用检查存在警告。
  • incomplete：回答未完整生成。完整生成也不代表证据一定充分。

请求失败时怎么处理

非 200 响应可读取 JSON 中的 detail。例如服务忙碌时：

{"detail": "问答服务正在处理其他问题，请稍后重试。"}
HTTP 状态码处理方式
422检查请求是否是 JSON、是否包含非空且不超过 500 字符的 question。此时 detail 通常是校验错误列表。
503服务正在处理其他问题。按响应头 Retry-After 提示稍后再试，当前为 5 秒。
502问答或上游模型调用失败，请稍后再试；持续出现时联系网站维护者。
504网站等待超时。后台调用可能仍在结束，不要立即反复重发。

如果程序提示“连接失败”，先确认网站地址、端口以及服务是否已启动。127.0.0.1 代表调用程序所在的电脑；其他电脑调用时需要网站实际可访问的地址。
